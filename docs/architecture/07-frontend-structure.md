# 07 — React frontend structure

React + TypeScript (strict) + Vite + Tailwind v4 + shadcn/ui (Radix) + Zustand + TanStack Query. The visual source of truth is the **L8Play design system** (Ember / Rosé themes): its `tokens.json` becomes CSS variables and Tailwind theme values. Components are rebuilt in TSX from its specifications rather than redesigned.

```
src/
  main.tsx
  app/
    App.tsx                    # providers + router outlet
    providers.tsx              # QueryClient, theme, toaster, i18n (optional)
    router.tsx                 # routes below
  styles/
    tokens.css                 # generated from design-system tokens.json (both themes)
    globals.css                # Tailwind entry, @theme mapping to tokens, base styles
  assets/fonts/                # Outfit, JetBrains Mono (OFL), bundled locally
  lib/
    tauri/
      commands.ts              # typed wrappers: invoke<Dto>('command', args)
      events.ts                # typed listen() helpers per event
      errors.ts                # CommandError → user-facing message
    bindings/                  # GENERATED by ts-rs — never edit
    query-keys.ts              # TanStack Query keys; event → invalidation map
    format.ts                  # sizes, durations, relative dates
  stores/                      # UI-only state (no server data)
    ui-store.ts                # theme, nav expanded, active dialog
    library-view-store.ts      # filters, sort, grid/list
  components/
    icons.ts                   # design-system icon names → Lucide components
    ui/                        # shadcn primitives restyled: button, icon-button, dialog, dropdown-menu,
                               # tabs, tooltip, switch, checkbox, radio-group, progress, input, textarea
    shell/                     # AppWindow, CaptionBar (window controls), NavRail, QuickRail, TopBar
    game/                      # Art (with fallback chain), GameCard, GameTile, GameRow, GameHero, HeroCard
    snapshot/                  # SnapshotCard, SnapshotTimeline, StorageTags, Protection
    feedback/                  # StatusBadge, Banner, EmptyState, ProtectionOrb, TransferRow, ActionRow,
                               # ActivityItem, skeletons
  features/
    dashboard/                 # DashboardPage + hooks
    library/                   # LibraryPage (grid/list), filters, add-game flow
    game-details/              # GameDetailsLayout, OverviewTab, SavesTab, ArtworkTab, PropertiesTab
    snapshots/                 # CreateSnapshotDialog, RestoreDialog, DeleteSnapshotDialog
    save-manager/              # SaveManagerPage, filters, detail panel
    cloud/                     # CloudPage, ConnectDriveFlow, ConflictDialog
    settings/                  # SettingsPage + one file per section (8)
    onboarding/                # OnboardingFlow (5 steps)
    artwork/                   # ArtworkPicker
  test/                        # vitest setup, Tauri IPC mocks
```

## Rules

- **Server state** (games, snapshots, sync) lives in TanStack Query, fetched through `lib/tauri/commands.ts` and refreshed by backend events. **UI state** (filters, theme, open dialog) lives in Zustand. They never mix.
- Feature folders own their pages, hooks and dialogs. Shared visuals live in `components/`.
- No component over about 200 lines. Logic goes to hooks (`useCreateSnapshot`, `useRestoreSnapshot`, `useLaunchGame`).
- Every data view implements loading (skeleton), empty (EmptyState), error (Banner with retry) and success states, as specified in the design system.
- Destructive or overwriting actions only run from a confirmation dialog whose button names the outcome.
- Window chrome: `decorations: false`; CaptionBar implements minimize / maximize / close through the Tauri window API, with a drag region.
- Accessibility: Radix primitives for focus management; the `focus` token ring; every icon-only button gets a label.
- Optional i18n (Lingui): all user-facing strings externalized from the start, so French can be added without refactoring. Approval needed (see the roadmap).
